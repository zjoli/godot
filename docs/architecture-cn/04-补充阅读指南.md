# 04 补充阅读指南

本篇补的是「读这个项目时,如果你不知道就会踩坑」的内容:构建方式、编译器开关、线程规则、
内存规则、扩展点在哪里、测试怎么跑、以及每块代码归谁管。

---

## 1. 构建与编译

```bash
# 编辑器(默认 target=editor)
scons platform=linuxbsd target=editor dev_build=yes -j$(nproc)

# 游戏模板(无编辑器代码)
scons platform=linuxbsd target=template_release production=yes

# 最小化构建示例
scons platform=linuxbsd disable_3d=yes module_mono_enabled=no module_gdscript_enabled=yes

# 运行单元测试
./bin/godot.linuxbsd.editor.dev.x86_64 --test
```

| 概念 | 说明 |
| --- | --- |
| `target` | `editor` / `template_release` / `template_debug`,决定 `TOOLS_ENABLED` 与优化级别 |
| `platform` | `windows` / `linuxbsd` / `macos` / `android` / `ios` / `visionos` / `web` |
| `dev_build` | 打开 `DEV_ENABLED`:额外断言、详细日志,性能显著下降 |
| `production` | 面向发行的默认值组合(优化、无调试符号) |
| `threads` | 是否启用多线程支持(部分平台受限) |
| `precision` | `single` / `double`(双精度构建影响所有 `real_t`) |
| `deprecated` | 是否编译已废弃 API(对应 `DISABLE_DEPRECATED` 取反) |
| `module_<name>_enabled` | 单个模块开关,`name` 即 `modules/` 下的目录名 |
| `disable_3d` / `disable_physics_3d` / `disable_navigation_3d` / `disable_xr` | 功能裁剪(裁 3D 会连带裁掉物理 3D 与 XR) |
| `vulkan` / `d3d12` / `metal` / `opengl3` / `forward_plus_renderer` / `forward_mobile_renderer` | 渲染后端开关 |

**关键构建机制**:

- `SConstruct` 是唯一的配置真相,`methods.py` 提供工具函数,`*/SCsub` 决定目录内源文件如何编译。
- **SCU(单一编译单元)编译**:`scu_builders.py` 把多个 `.cpp` 合并成一个,加快构建,但会掩盖
  缺 include 的问题——所以本地改动后建议 `scu_builders.py` 关闭或注意 include 完整性。
- **构建期代码生成**:`*.gen.h` / `*.gen.cpp` 是生成产物(如 `modules_enabled.gen.h`、
  `register_module_types.gen.cpp`、`gdextension_interface.gen.h`),不在版本库中;
  搜索「找不到文件」时先确认是否已构建过一次。
- 编译告警会通过 `.clang-format` / `.clang-tidy` / `.clangd` 与 `pre-commit` 约束,见 `misc/scripts/`。

## 2. 编译期宏与裁剪(读代码必知)

代码里到处是条件编译,读之前先确认自己在哪个组合下。

| 宏 | 含义 | 影响范围 |
| --- | --- | --- |
| `TOOLS_ENABLED` | 是否包含编辑器 | 整个 `editor/`,以及 `scene/`、`servers/` 内的编辑器辅助分支 |
| `DEV_ENABLED` | `dev_build=yes` | 额外的 `DEV_ASSERT`、校验、慢路径 |
| `TESTS_ENABLED` | 是否编译 `tests/` | `Main::test_setup()` 等 |
| `_3D_DISABLED` / `PHYSICS_3D_DISABLED` / `NAVIGATION_3D_DISABLED` / `XR_DISABLED` | 3D 相关裁剪 | `scene/3d`、`servers/physics_3d` |
| `MODULE_<NAME>_ENABLED` | 模块是否开启 | 由 `modules_enabled.gen.h` 生成 |
| `DISABLE_DEPRECATED` | 关闭兼容代码 | 所有 `.compat.inc` 与 `_deprecated` 绑定 |
| `DEBUG_ENABLED` / `DEBUG_METHODS_ENABLED` | 调试构建 | 参数校验、方法名信息 |
| `RD_ENABLED` / 渲染后端宏 | 是否编译某个渲染后端 | `servers/rendering`、`drivers/` |
| `ACCESSKIT_ENABLED` / `SDL_ENABLED` | 可选驱动 | `drivers/accesskit`、`drivers/sdl` |
| `GLES3_*` / `VULKAN_*` 等 | 后端细节 | 驱动内部 |

**读代码技巧**:遇到 `#ifdef` 分支,先看 `SConstruct` 里对应选项的默认值,再决定哪条是主线。
例如 `TOOLS_ENABLED` 在 `target=editor` 下为真,所以「编辑器才有的行为」默认就能看到。

## 3. 线程模型

```
主线程(Main) ─┬─ 场景树、脚本、输入、UI、大部分 API
              ├─ MessageQueue.call_deferred → 回主线程执行
              ├─ 物理：默认在主线程内分步执行
              │    (PhysicsServer 的 WrapMT 只是把 API 变为命令队列,并非独立线程)
              ├─ 渲染线程(可选)：RenderingServerWrapMT + CommandQueueMT，
              │    RenderingServer::sync() / end_sync() 是同步点
              ├─ 音频线程：AudioDriver 回调 → AudioServer::_mix_step()
              └─ WorkerThreadPool：并行任务(Builder、资源加载、网格生成)
```

规则与陷阱:

- **`Node` 与 `Resource` 的绝大多数 API 只能在主线程调用**;跨线程要用 `call_deferred` 或
  `WorkerThreadPool::add_task` + `MessageQueue` 回到主线程。
- `set_current_thread_safe_for_nodes(true)` 用于测试等特殊场景,**不是**通用的线程安全开关。
- `SafeRefCount`、`SafeNumeric`、`CommandQueueMT` 是引擎自带的跨线程原语。
- 渲染线程开启时,主线程写命令、渲染线程执行,`RenderingServer::sync()` 之后命令才可见;
  这就是「改了属性但画面延迟一帧」的原因。
- 音频线程**绝不能**阻塞;`AudioServer` 中涉及主线程数据的部分用原子量/无锁队列提交。
- 物理后端线程化时,`PhysicsServer3D::sync/flush_queries/end_sync` 是保证「本帧命令可见性」的屏障
  (`main/main.cpp:4965` 一带)。

## 4. 内存与对象寿命

| 机制 | 说明 | 规则 |
| --- | --- | --- |
| `memnew` / `memdelete` | 引擎自己的分配宏,接入内存追踪 | 继承 `Object` 的对象用它们;不要用 `new/delete` |
| `RefCounted` + `Ref<T>` | 引用计数,自动释放 | `Resource` 与多数工具类;注意循环引用会泄漏 |
| `Node` | **不受引用计数管理** | 只能 `add_child`/`remove_child`/`queue_free`,不要 `Ref<Node>` |
| `RID` | 句柄,不是对象 | 谁创建谁释放;`Node::_exit_tree` 与 `NOTIFICATION_PREDELETE` 是释放点 |
| `CowData` | 写时复制缓冲 | `Vector`/`String`/`PackedByteArray` 的共享语义;`write[]` 会触发拷贝 |
| 内存追踪 | `core/os/memory.cpp` | `--verbose` 构建会在退出时报告泄漏;`dev_build` 有更严格的检查 |

常见陷阱:

- `queue_free()` 是**延迟**释放,之后访问该节点可能仍然有效但状态不确定;
  用 `is_queued_for_deletion()` 判断。
- `ObjectID` 是弱引用,可用于在回调中安全地判断对象是否已销毁。
- 持有 `RID` 的对象销毁时必须同步调用 `RS::free_rid` 之类的接口,否则渲染侧泄漏(表现为内存缓慢增长)。

## 5. 绑定与反射约定(改 API 时必看)

```cpp
// 头文件
class MyNode : public Node {
    GDCLASS(MyNode, Node);

    int value = 0;
    void set_value(int p_v) { value = p_v; }
    int get_value() const { return value; }

protected:
    static void _bind_methods();          // 注册方法/属性/信号
    void _notification(int p_what);       // 生命周期通知

public:
    void do_something();                  // 会被绑定
    GDVIRTUAL1(my_virtual, int)           // 可被 GDExtension/脚本重写的虚方法
};
```

```cpp
// 源文件
void MyNode::_bind_methods() {
    ClassDB::bind_method(D_METHOD("do_something"), &MyNode::do_something);
    ClassDB::bind_method(D_METHOD("set_value", "value"), &MyNode::set_value);
    ClassDB::bind_method(D_METHOD("get_value"), &MyNode::get_value);
    ADD_PROPERTY(PropertyInfo(Variant::INT, "value"), "set_value", "get_value");
    ADD_SIGNAL(MethodInfo("something_happened"));
    GDVIRTUAL_BIND(my_virtual, "arg");
}
```

要点:

- **每个公开类都要 `GDCLASS` + `_bind_methods`**,否则脚本/编辑器看不见它;
  注册入口在各 `register_*_types.cpp`。
- `D_METHOD("name", "arg1", ...)` 提供参数名,影响编辑器与文档,务必与参数顺序一致。
- 物理/渲染等服务层使用 `RSE::` / `PSE::` 等命名空间做枚举转换,避免把内部枚举暴露给脚本。
- 有 `ptrcall` 快速路径:**参数类型不匹配会直接崩溃**,因此 `Variant` 转换必须严格。
- 文档与代码同步:`doc/classes/*.xml` 是唯一真源,新增 API 后要么手写 XML,要么用
  `--doctool` 生成骨架再补描述;`misc/scripts/validate_xml.py` 与 CI 会校验。

## 6. 兼容层:`*.compat.inc`

- 每个大版本会移除若干 API。为了让「旧脚本/旧扩展仍能编译但给出警告」,引擎把已废弃的绑定放在
  `xxx.compat.inc` 中,由 `DISABLE_DEPRECATED` 控制是否编译。
- 读代码时看到 `#include "xxx.compat.inc"` 可以暂时跳过——它们是历史兼容,不是当前设计。
- 对 GDExtension 还有一层:`gdextension_special_compat_hashes.cpp` 让旧版本生成的绑定在
  方法签名变化后仍能匹配,`--validate-extension-api` 用于 CI 检测破坏性变更。

## 11. 代码风格与 CI 校验

- `.clang-format`(格式化)、`.clang-tidy`(静态分析)、`.clangd`(编辑器集成)。
- 命名约定:`PascalCase` 类型、`snake_case` 成员与函数、成员变量以 `_` 结尾、参数 `p_xxx`、
  私有方法 `_xxx`、常量 `ALL_CAPS`;全局单例 `XxxServer::get_singleton()`。
- include 顺序由 `misc/scripts/validate_includes.py` 校验;文件头版权由 `copyright_headers.py` 校验;
  `file_format.py` 检查尾随空格/换行等;`header_guards.py` 检查 `#pragma once`;
  `validate_xml.py` 校验文档;`validate_extension_api.sh` 校验 API 兼容性。
- `pre-commit` 配置在 `.pre-commit-config.yaml`,本地可一键跑全部检查。

## 12. 平台移植清单(新增一个平台要做什么)

按依赖顺序实现下列接口,每项都是独立可分配的子任务:

1. **入口与 OS 层**:`main()` 封装、`OS` 子类(时间、环境变量、进程、内存信息、路径)。
2. **显示**:`DisplayServer` 子类(窗口创建/尺寸/输入事件/剪贴板/IME/DPI/多屏/光标/原生菜单)。
3. **图形上下文**:`RenderingContextDriver`(窗口 → GPU 表面)、`RenderingDeviceDriver`(若走 RD)。
4. **音频**:`AudioDriver`(输出回调或拉模式)。
5. **输入映射**:原生键码 → Godot `Key`,手柄轴/按钮映射。
6. **文件系统**:`FileAccess` / `DirAccess` 子类(若平台有特殊路径语义与权限模型)。
7. **线程与同步**:`Thread` / `Mutex` / `Semaphore` 的适配(很多平台直接用 POSIX/`std::thread` 实现)。
8. **崩溃与日志**:`crash_handler_*`、平台终端日志。
9. **构建**:`platform/<name>/detect.py`、`SCsub`、`platform_config.h`、导出模板与 `export/`。
10. **平台 API 注册**:更新 `platform/register_platform_apis.h` 与 `platform/SCsub`。

可参考的对照实现:`platform/linuxbsd`(X11 + Wayland 双实现)、`platform/web`(Emscripten 主循环)、
`platform/visionos`(存在感最小、最近新增)。

## 15. 分角色阅读路线

**新人(第一周)**

1. `core/object/object.h` + `class_db.cpp` 的绑定宏 → 理解对象与反射。
2. `scene/main/node.h` + `scene_tree.cpp` → 理解生命周期与每帧驱动。
3. `main/main.cpp` 的 `setup/setup2/start/iteration` → 理解整个引擎怎么跑起来。
4. 跑一次 `--test` 与最小项目,建立「改代码 → 看效果」的回路。

**要做渲染相关工作**

`rendering_server.h` → `renderer_viewport.cpp` → `renderer_scene_cull.cpp` →
`renderer_rd/renderer_scene_render_rd.cpp` → `rendering_device.cpp` → `drivers/vulkan`(或 metal/d3d12)。
辅以 `storage_rd/` 理解资源注册,`shader_language.cpp` 理解着色器编译。

## 16. 术语表

| 术语 | 含义 |
| --- | --- |
| `RID` | Resource ID,跨层句柄,不是对象 |
| `Server` | 单例服务层,如 `RenderingServer` |
| `Rasterizer` | 旧命名,现指某个渲染后端实现(如 `RasterizerSceneGLES3`) |
| `RD` | `RenderingDevice`,统一 GPU 抽象层 |
| `RD` 后缀类 | `*RD` 表示基于 `RenderingDevice` 的实现 |
| `WrapMT` | 多线程包装层,把 API 变成命令队列 |
| `SCU` | Single Compilation Unit,合并编译以加速构建 |
| `PCK` | Godot 自定义资源包格式 |
| `.godot/` | 项目本地缓存(导入产物、UID 缓存),不进版本控制 |
| `UID` | 资源唯一标识,替代路径引用 |
| FTI | Fixed Timestep Interpolation,固定时间步插值 |
| `_process` / `_physics_process` | 逻辑帧 / 物理帧回调 |
| `notification` | 引擎内部的生命周期事件广播(整数) |
| `GDCLASS` / `GDVIRTUAL` | 绑定与虚方法宏 |
| GDExtension | 二进制 C ABI 扩展机制 |
| `compat.inc` | 旧 API 兼容绑定文件 |
| `EditorPlugin` | 编辑器扩展点 |
| `MultiplayerPeer` | 多人传输抽象 |

## 17. 最容易踩的十个坑

1. 在 `_draw()` 之外调用绘制 API → 直接报错。
2. 以为 `queue_free()` 是立即释放 → 帧末才释放,期间对象仍可能被回调访问。
3. 在物理帧之外使用 `PhysicsDirectSpaceState` 查询 → `space is locked` 报错。
4. 把 `Node` 存进 `Ref<Node>` → 语义错误,节点生命周期不由引用计数管理。
5. 忘记释放 `RID` → 渲染侧资源泄漏。
6. 忘了 `_bind_methods()` 注册 → 脚本侧方法不存在。
7. `D_METHOD` 参数名与顺序不一致 → 编辑器/文档显示错乱,调用参数错位。
8. 跨线程直接改 `Node` → 随机崩溃;应 `call_deferred`。
9. 改动后忘了 `doc/classes/*.xml` → CI 的文档校验失败。
10. 在 `TOOLS_ENABLED` 分支里写了发行版需要的代码 → 模板构建缺符号。
