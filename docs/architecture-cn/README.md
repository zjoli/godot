## 建议阅读顺序

1. 先读 `01` 的「分层模型」与「依赖规则」,建立 `core → servers → scene → editor` 的心理模型。
2. 再读 `02` 的总表,明确每个目录归谁管、边界在哪里。
3. 读到具体功能时,用 `03` 的时序图定位入口函数,再去 `04` 查编译开关与线程约束。

## 一句话总结

Godot 是一个「**Server + Node 双层架构**」的游戏引擎:`scene` 层是暴露给游戏开发者、可序列化的高层
对象;`servers` 层是底层实现,通过 `RID` 句柄管理真实资源;`drivers` 与 `platform` 把图形 API、窗口、
音频设备抽象为可替换后端;`core` 提供对象模型、容器、IO 与数学基础;`editor` 是构建在 `scene` 之上的
一个特殊 GUI 应用;`main` 负责按序初始化以上各层并驱动主循环;`modules` 则是以「可裁剪编译单元」
形式存在的功能扩展。

## 阅读时的三个心智锚点

- **`Object` 是一切对象的根**:`Node`(场景对象)、`Resource`(可序列化资源)、`RefCounted`(引用计数对象)、
  `Server` 单例都继承自它,`ClassDB` 提供运行时反射。
- **`RID` 是跨层句柄**:`Node` 里持有 `RID`,真正的数据在 `servers` 中;节点销毁必须显式释放 `RID`。
- **`Notification` + `_process` 是驱动机制**:引擎用整数通知(notification)自上而下广播生命周期事件,
  用 `_process` / `_physics_process` 驱动每帧逻辑。
