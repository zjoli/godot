# 02 功能模块与子模块划分

## 0. 划分原则

- **模块**= 可独立排期、可独立裁剪的纵向功能切面,粒度约等于「一个子团队」。
- **子模块**= 具有清晰边界的功能单元,满足两个条件:
  1. 可以把「维护责任」整体交给一名开发人员;
  2. 是理解该功能、阅读细节时的最小自洽单元(不需要先读完别的子模块才能读懂它)。
- 子模块的**边界判据**:它有稳定的对外接口(类名/API 名)、独立的目录或文件集合、明确的依赖方向。

## M1 对象模型与变体

**定位**:引擎的「类型系统内核」。这一层不依赖任何其他层,是理解整个项目的起点。

| 子模块 | 路径 | 职责 | 关键类型 | 对外接口 |
| --- | --- | --- | --- | --- |
| 对象基类 | `core/object/object.h/.cpp` | 属性读写、方法调用、信号、通知、元数据、`_notification` 分发 | `Object`、`ObjectID` | `set/get/call/connect/emit_signal/notification` |
| 反射与注册 | `core/object/class_db.*`、`method_bind.*`、`method_info.*`、`property_info.*` | 类注册、方法绑定、继承链、`ClassDB::instantiate` | `ClassDB`、`MethodBind`、`MethodInfo`、`PropertyInfo` | `_bind_methods()`、`D_METHOD` |
| 引用计数 | `core/object/ref_counted.*` | `Ref<T>` 智能指针与循环引用检测 | `RefCounted`、`Ref<T>` | `reference()/unreference()` |
| 脚本接口 | `core/object/script_language.*`、`script_instance.*`、`script_backtrace.*` | 语言无关的脚本抽象、实例转调、异常回溯 | `ScriptLanguage`、`ScriptInstance`、`ScriptBacktrace` | `ScriptLanguage::get_singleton()` |
| 消息队列 | `core/object/message_queue.*` | 延迟调用(`call_deferred`)、跨线程投递 | `MessageQueue` | `MessageQueue::push_callable` |
| 撤销栈 | `core/object/undo_redo.*` | 编辑器撤销/重做的最小内核 | `UndoRedo` | `create_action/commit_action` |
| 线程池 | `core/object/worker_thread_pool.*` | 任务化并行(`WorkerThreadPool::add_task`) | `WorkerThreadPool` | `add_group_task/add_task` |
| 变体 | `core/variant/variant.*`、`variant_call.cpp`、`variant_op.cpp`、`variant_setget.cpp` | 动态类型值、类型转换矩阵、运算分派、`Variant::call` | `Variant`、`VariantInternal` | 全部绑定 API 的参数类型 |
| 容器类型 | `core/variant/{array,dictionary,typed_array,typed_dictionary}.h` | `Array`/`Dictionary` 及类型化容器 | `Array`、`Dictionary`、`TypedArray<T>` | 脚本容器 API |

**读法建议**:先读 `object.h` 的 `_notification` 与 `connect`,再读 `class_db.cpp` 的
`bind_method` 宏展开链,最后读 `variant.cpp` 的 `Variant::operator=`(类型分派核心)。
